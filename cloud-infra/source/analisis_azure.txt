1. Estructura de Suscripciones Azure
La organización en Azure se compone de tres suscripciones principales:
Open Prod SubscriptionDestinada a entornos productivos, donde deberían residir los sistemas críticos con acceso restringido. 
Open Operations SubscriptionUtilizada para entornos de desarrollo, testing y herramientas internas (AKS dev/test, DevOps, etc.). 
Azure Subscription 1Actualmente sin uso activo. 
Esta segmentación es adecuada desde el punto de vista organizativo, aunque requiere validación a nivel de red y seguridad para garantizar aislamiento efectivo entre entornos.


2. Organización por Resource Groups
Los recursos en Azure se encuentran organizados en dos grupos principales:
rg-open-prodContiene los recursos productivos dentro de la suscripción Open Prod. 
rg-open-devtestContiene los recursos de desarrollo y testing dentro de la suscripción Open Operations. 
Esta estructura permite una separación lógica adecuada entre entornos, facilitando la administración y control de accesos.

A1. Tráfico VPN Azure ↔ Datacenter (Producción)
Se realizó el análisis de tráfico de la conexión Site-to-Site (S2S) entre Azure y el datacenter on-premise utilizando métricas de rendimiento disponibles en Azure Monitor.
Métricas analizadas:
BitsInPerSecond (Avg): tráfico entrante a Azure desde el datacenter 
BitsOutPerSecond (Avg): tráfico saliente desde Azure hacia el datacenter 
Período analizado:
Últimos 30 días 

Resultados observados:
Tráfico promedio entrante (On-Prem → Azure): 
~75 bits por segundo 
Tráfico promedio saliente (Azure → On-Prem): 
~13 bits por segundo 
Se observan picos aislados de tráfico, con valores máximos aproximados: 
Hasta ~6 Kb/s en tráfico entrante 
Hasta ~1 Kb/s en tráfico saliente 
Durante la mayor parte del período: 
El tráfico se mantiene prácticamente en 0 bps 
No se evidencia uso sostenido del túnel VPN 


Observaciones técnicas:
El tráfico registrado es extremadamente bajo en relación a una operación continua de aplicaciones. 
La comunicación a través del túnel VPN es: 
Intermitente 
De baja intensidad 
No se identifican patrones de uso constante ni cargas sostenidas de datos. 
El tráfico parece corresponder a: 
consultas puntuales 
validaciones esporádicas 
integraciones no continuas

A4. Tráfico VPN Azure ↔ Datacenter (Dev/Test)
Se realizó el análisis del tráfico de la conexión Site-to-Site (S2S) entre Azure y el datacenter on-premise correspondiente al entorno de desarrollo y testing, utilizando métricas de Azure Monitor.
Configuración analizada
Recurso: open-pfsense-connection-devtest 
Métricas: 
BitsInPerSecond (Avg): tráfico entrante a Azure 
BitsOutPerSecond (Avg): tráfico saliente desde Azure 
Período: Últimos 30 días 

Resultados observados
Tráfico promedio entrante (On-Prem → Azure): → ~65.2 bits por segundo 
Tráfico promedio saliente (Azure → On-Prem): → ~4 bits por segundo 
Picos de tráfico observados: 
Hasta ~4–5 Kb/s en tráfico entrante 
Tráfico saliente prácticamente nulo en comparación 

Comportamiento del tráfico
El tráfico es extremadamente bajo durante la mayor parte del período. 
Se observan picos aislados sin continuidad en el tiempo. 
No existe tráfico sostenido ni patrones de uso constantes. 
El tráfico entrante es significativamente mayor que el saliente. 

Observaciones técnicas
La VPN se encuentra operativa (estado: Conectado). 
El uso del túnel es: 
Intermitente 
De muy baja intensidad 
El flujo principal es: 
On-Premise → Azure 
Esto indica que la VPN en Dev/Test se utiliza principalmente para: 
Pruebas puntuales 
Validaciones de conectividad 
Integraciones esporádicas
