# Relevamiento de alta de cliente — camino punta a punta (Maipú)

**Objetivo:** el mismo que [`plan_relevamiento_alta_cefas.md`](plan_relevamiento_alta_cefas.md), [`plan_relevamiento_alta_jobs.md`](plan_relevamiento_alta_jobs.md), [`plan_relevamiento_alta_eby.md`](plan_relevamiento_alta_eby.md), [`plan_relevamiento_alta_boca.md`](plan_relevamiento_alta_boca.md), [`plan_relevamiento_alta_abb.md`](plan_relevamiento_alta_abb.md), [`plan_relevamiento_alta_roman.md`](plan_relevamiento_alta_roman.md), [`plan_relevamiento_alta_giar.md`](plan_relevamiento_alta_giar.md), [`plan_relevamiento_alta_argocean.md`](plan_relevamiento_alta_argocean.md) y [`plan_relevamiento_alta_rex.md`](plan_relevamiento_alta_rex.md) — entender capa por capa qué infraestructura usa un cliente (dominio → NPM → firewall/NAT → app → DB → storage) recorriéndolo de punta a punta.

**Motor, app Docker/reportes, DB y storage cerrados en una sola sesión (15 sep 2026) — el firewall queda como único cabo suelto.** Maipú (Diagnóstico Maipú) figuraba en el inventario como "en alta, incompleto" — igual que Heinlein, aparece en el inventario técnico pero no en la tabla funcional de la matriz (la hoja Discrepancias lo dice explícito: *"Heinlein y Maipú aparecen en el inventario técnico, pero no en la tabla funcional. Se agregaron para no perder visibilidad"*). A diferencia de Heinlein, acá no hizo falta perseguir una pista enterrada — una sesión directa de consola vCenter sobre `DMWL01` (root, tras timeout del dashboard de `DMFW01`) cerró cuatro capas de un tirón. Lo que se llevó la sesión fue un hallazgo colateral: el WebLogic de Maipú no es un host dedicado.

## Hallazgo: `DMWL01` no es exclusivo de Maipú

El `formsweb.cfg` de `DMWL01` (`base_domain`) tiene, además de las secciones propias de Maipú (`DMprodFSAL`/`DMprod2` para producción, `DMQAFSAL`/`DMQA`/`activaciondmqa` para QA), secciones activas de **CEFAS, GIAR, EBY y Rex-test** (`rextest`, `cefasprod`, `cefasprodFSAL`, `giargprod`, `activaciongiarg`, `ebyprodFSAL`, `ebyprod`, entre otras). Cuatro copias del archivo conviven en el filesystem (config viva, caché temporal, backup en `domain_bak/config_prev`, y una versión `pending/` sin aplicar todavía) — consistente con un dominio que se sigue tocando activamente, no un host abandonado.

La lectura más probable es que `DMWL01` sea una réplica/DR del dominio WebLogic compartido que ya conocíamos por `OPENWLPROD01`/`WebLogic.191` (EBY/GIAR/ROMAN/CEFAS), no un segundo dominio independiente. **Sin confirmar todavía** si esas secciones ajenas sirven tráfico real desde acá o son config legado sin uso — no se buscó evidencia de sesiones activas de esos otros clientes en este host, solo se siguió el rastro de Maipú.
